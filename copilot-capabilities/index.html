Copilot Interaction Modes

Understanding when to use each mode is critical. The exam tests scenario-based questions about mode selection.

Agent Mode

How Agent Mode Works

  • Copilot acts autonomously — it decides which files to touch and what changes to make
  • Can create, edit, and delete files across the entire repository
  • Runs terminal commands: builds, tests, dependency installs, linters
  • Iterates on its own errors — if a build fails, it diagnoses and fixes automatically
  • Delegates sub-tasks to Sub-Agents for optimized context usage
  • Available in VS Code (Copilot Chat panel) and GitHub.com
  • Cloud Agent: A version of Agent Mode that runs remotely on GitHub infrastructure, not locally

When to Use Agent Mode

  • Complex feature implementations spanning many files
  • Setting up an entire project scaffold from scratch
  • Automated refactoring across a large codebase
  • When you want maximum autonomy and can review the result at the end

Edit Mode

How Edit Mode Works

  • You select which files Copilot is allowed to edit
  • Copilot proposes changes step-by-step and you approve each iteration
  • More controlled than Agent Mode — Copilot cannot touch files outside your selection
  • Available in VS Code and JetBrains IDEs

When to Use Edit Mode

  • Focused refactoring of a known set of files
  • Applying a consistent change across multiple specified files
  • When you need control over exactly what is modified

Plan Mode

  • Copilot produces a detailed implementation plan before any code changes are made
  • Plan lists which files will be created, edited, or deleted with explanations
  • You review and approve the plan before execution begins
  • After approval you can hand off to Agent Mode or Edit Mode for execution
  • Best for: complex tasks where you want full upfront visibility

Agent Sessions & Sub-Agents

  • Agent Sessions maintain context across multiple steps of a multi-part task
  • Sub-Agents handle isolated delegated tasks with their own independent context windows
  • Architecture prevents context window exhaustion on large tasks
  • Sub-Agents report results back to the orchestrating agent session
  • Enables parallelism — multiple sub-tasks can run concurrently

Model Context Protocol (MCP)

MCP is an open protocol that extends Copilot's capabilities by connecting it to external tools, services, and data sources. Reference: Extending Copilot with MCP.

Key MCP Concepts

  • Connects Copilot to external systems: databases, APIs, Jira, Slack, Teams, Azure Boards, Linear
  • Configured via MCP servers that expose tools and resources to Copilot
  • On GitHub.com, the GitHub MCP server is automatically configured — enables branch creation, PR merging, issue management directly from Copilot Chat
  • Organizations can manage MCP availability via the MCP policy in admin settings
  • Enterprise owners control whether users can connect MCP servers

Policy Levels for MCP

  • Enterprise: enable/disable MCP for all orgs, or delegate to org owners
  • Organization: enable/disable MCP for the org's members
  • Access controlled under AI Controls > Model Context Protocol (MCP)

Code Review & Coding Assistance

Copilot Code Review

  • Reviews pull requests on GitHub.com with AI-powered feedback
  • Identifies bugs, security issues, style violations, and suggests improvements
  • Configured with customizable review standards via instructions files
  • Admins toggle it via Settings > Copilot > Code review
  • Custom instructions for code review are pulled from the PR's base branch
  • Org admins enable Copilot Code Review policies to roll it out org-wide
  • Also available in supported IDEs for "Review selection" (Free plan: VS Code only)

Spaces, Spark & PR Summaries

Copilot Spaces

  • Curated workspaces combining code, documentation, and context
  • Gives Copilot a richer, more focused view of a project or area
  • Shareable with team members for consistent AI assistance
  • Helps reduce context ambiguity in large mono-repos

GitHub Spark

  • AI-powered tool for building small web applications using natural language — no coding required
  • Creates functional micro-apps and prototypes quickly
  • Apps can be deployed from the CLI or web interface
  • Uses prompt engineering techniques to refine the app iteratively

Pull Request Summaries

  • Copilot automatically generates a summary of PR changes
  • Describes what changed, why, and potential impact
  • Helps reviewers quickly understand a PR's scope without reading every diff line
  • Available to all plans on GitHub.com

Custom Instructions & Prompt Files

Custom instructions let you tailor Copilot's behavior without repeating context in every prompt. Reference: Adding custom instructions.

Instructions File Locations & Priority

File / LocationScopePriority
Personal instructions (GitHub.com profile settings)All repositories for the userHighest
.github/copilot-instructions.mdEntire repositoryMiddle
Organization-level instructionsAll repos in the orgLowest

When multiple levels apply, all are provided to Copilot — not just the highest priority one.

Path-Specific Instructions

  • Create NAME.instructions.md files inside .github/instructions/
  • Use a frontmatter applyTo field with glob patterns to scope them:
---
applyTo: "app/models/**/*.rb"
---
Always use ActiveRecord validations, never raw SQL.
  • Use excludeAgent to prevent an instruction file from applying to a specific agent:
---
applyTo: "**"
excludeAgent: "code-review"
---
  • Path-specific instructions currently apply to Copilot cloud agent and Copilot code review on GitHub.com

Agent-Specific Files

  • Repositories can also contain AGENTS.md, CLAUDE.md, or GEMINI.md for agent-specific guidance

Prompt Files

  • Reusable prompt templates stored in the repository
  • Shared across the team for consistent Copilot responses
  • Reduce variance in AI output for common tasks (e.g., "write a REST endpoint")
⚠ Exam Tip — Instructions Priority

Know the priority order: Personal > Repository > Organization. Also know that when multiple levels are active, all sets of instructions are provided to Copilot — they are not mutually exclusive.

Chat Limits, Feedback & Commands

  • Chat has rate limits that vary by plan (see plans table below)
  • Users provide feedback via 👍/👎 on responses to improve Copilot
  • Chat history within a session is included in the prompt, consuming context window tokens
  • Starting a new chat session resets context — useful when a conversation goes off track
  • Inline chat (Ctrl+I) targets selected code or the cursor position

GitHub's current documentation refers to the monthly usage allowance as "GitHub AI Credits" (the same concept historically called "premium requests"). Exact numeric allowances for Max and for AI-credit-denominated tiers are not published as fixed figures — know it qualitatively as "the highest individual allowance," scaled above Pro+.

⚠ Critical Exam Fact

Content exclusions, org-wide policy management, and audit logs are Business/Enterprise-only — this includes Max, which is still an individual plan with no org-admin controls. Data is not retained for model training on Business/Enterprise. Individual plans (Free, Pro, Pro+, Max) can opt in or out of training data usage.

ⓘ What Is Copilot Max?

GitHub Copilot Max ($100/month) is the top individual tier, sitting above Pro+. It targets sustained, high-volume individual users: the highest individual AI-credit allowance plus priority access to new models and features before they roll out more broadly. Functionally it matches Pro+ on Agent Mode, Cloud Agent, MCP, and model catalog access — the differentiators are allowance size and priority rollout, not new capabilities.

Organization-Wide Management

Policy Management

Three Policy Categories (AI Controls)

  1. Agents — control AI agent (cloud agent) availability
  2. Copilot — control Copilot feature availability (suggestions, chat, code review, etc.)
  3. Model Context Protocol (MCP) — control whether MCP server connections are allowed

Scope Hierarchy

  • Enterprise owners can define a policy for the entire enterprise, or delegate decisions to individual org owners
  • Organization owners configure policies for their org under Settings > Copilot
  • Implementation methods: dropdown menus, toggles, or named policy links
  • Specific controls: enable Copilot Code Review policies, manage feature availability across IDEs and github.com, enable user feedback collection

Audit Log Events

  • Copilot generates audit log events visible in the org/enterprise audit log on GitHub
  • Types of events tracked:
    • Seat assignments added or removed
    • Policy configuration changes (features enabled/disabled)
    • Content exclusion rule changes
    • Copilot usage activity (feature interactions)
  • Available on Business and Enterprise plans only
  • Used for compliance, security review, and governance
  • Reference: Reviewing audit log events for Copilot

REST API Subscription Management

The GitHub REST API provides dedicated endpoints for Copilot seat and billing administration at the organization level.

MethodEndpointPurpose
GET/orgs/{org}/copilot/billingOrg's Copilot subscription info: seat breakdown and feature policies
GET/orgs/{org}/copilot/billing/seatsLists every Copilot seat the org is currently billed for
POST/orgs/{org}/copilot/billing/selected_teamsGrants Copilot access to all members of specified teams
DELETE/orgs/{org}/copilot/billing/selected_teamsSets seats for those teams' members to "pending cancellation"
POST/orgs/{org}/copilot/billing/selected_usersGrants Copilot seat access to individual users
DELETE/orgs/{org}/copilot/billing/selected_usersSets seats for those users to "pending cancellation"
GET/orgs/{org}/members/{username}/copilotSeat details for one specific org member
GET/orgs/{org}/copilot/usageDaily aggregated usage metrics across the organization

All endpoints require organization-owner authorization plus the manage_billing:copilot or read:org scope (admin:org for write operations).

  • Useful for automating seat onboarding/offboarding scripts at scale (hundreds or thousands of developers)
  • "Pending cancellation" seats remain billed until the end of the current billing cycle — removal is not immediate
  • Content exclusion rules can also be managed via the REST API for bulk configuration
⚠ Exam Tip — Cancellation Is Not Instant

DELETE operations on seats set them to "pending cancellation", not immediate removal — the org is still billed until the cycle ends. Don't assume DELETE = instant access revocation.

💡 Study Tip

Review the plans table carefully. The exam frequently asks about which plan is required for a given feature. Know: content exclusions = Business+, audit logs = Business+, advanced models (Opus/Gemini 3 Flash) = Pro+, Max, or Enterprise, Agent Mode = Pro+ and above, priority model access = Max or Enterprise only.

Network Settings (Enterprise Rollouts)

  • Copilot continuously "interacts with a remote machine learning model and checks for updates" — corporate firewalls/proxies can block this traffic and cause suggestions to silently fail
  • Enterprises behind a restrictive firewall must allowlist the required Copilot domains before rollout (see the official allowlist reference below)
  • This is a common root cause when "Copilot works at home but not on the corporate network"
