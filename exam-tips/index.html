These are topics that commonly trip up exam takers. Each one is directly based on the official study guide skills and documentation.

4. Two Different "Copilot CLI" Tools — Don't Conflate Them

  • The old gh extension install github/gh-copilot extension is retired. It only had two commands: gh copilot suggest and gh copilot explain, with three suggestion types (generic shell, gh command, git command)
  • It has been replaced by the new standalone GitHub Copilot CLI, invoked with the bare copilot command (install via npm install -g @github/copilot, winget, brew, or curl script)
  • The new CLI is a full agentic tool — interactive mode (with Plan Mode via Shift+Tab) or programmatic mode (copilot -p "prompt") — not just a single-command suggester
  • The new CLI uses trusted directories and tool-approval flags (--allow-tool, --deny-tool, --allow-all-tools) as safety guardrails

4b. Premium Request Units (PRUs)

  • Agentic/premium operations consume PRUs, not flat "requests" — cost scales with task complexity and reasoning depth
  • Simple agent handoff ≈ 1 PRU; multi-agent draft-review flow ≈ 2–3 PRUs; premium reasoning roughly doubles cost (~4+ PRUs); large multi-file scaffolds ≈ 3–5 PRUs
  • Free plan: 50 premium requests/month; Pro: 300; Pro+: 1,500; Max: highest individual allowance ($100/mo, also gets priority access to new models/features); Business: 300/user; Enterprise: 1,000/user
  • GitHub's current docs increasingly call this allowance "AI credits" rather than "premium requests" — both terms refer to the same underlying concept

5. Developer Accountability Is Absolute

  • The developer is always responsible for committed code — not Copilot, not GitHub
  • This maps to the Accountability principle of Microsoft's Responsible AI framework
  • AI suggestions are drafts — they must be reviewed, tested, and validated
  • Copilot can suggest insecure code; security review remains the developer's responsibility

6. The Six Responsible AI Principles (Memorise Them)

In order: Fairness → Reliability & Safety → Privacy & Security → Inclusiveness → Transparency → Accountability

Mnemonic: "For Really Professional IT, Teams Are Accountable"

7. Custom Instructions Priority Order

  • Priority (highest first): Personal > Repository > Organization
  • All applicable instruction sets are combined and sent — not mutually exclusive
  • Repository-level: .github/copilot-instructions.md
  • Path-specific: .github/instructions/NAME.instructions.md with applyTo: frontmatter

8. Open Tabs Are Context (Prompt Engineering)

  • Other files open in the IDE actively influence inline suggestion quality
  • This is testable: open relevant files → better suggestions; close irrelevant ones → less noise
  • Know zero-shot (no examples) vs. few-shot (with examples) — and when each is more effective
  • Chat history within a session is context — long sessions accumulate token cost

9. Data Flow & Proxy Architecture

  • The proxy service sits between the IDE and the LLM — it is the enforcement point for all data policies
  • Content exclusions are checked before the prompt reaches the model (in the IDE and proxy)
  • Post-processing (duplication detection, safety filters) happens after model inference, at the proxy
  • Business/Enterprise prompts are never retained for model training — this is enforced by the proxy

10. Keyboard Shortcuts That Are Tested

  • Accept full suggestion: Tab
  • Dismiss suggestion: Esc
  • Next suggestion: Alt+] (Windows) / Option+] (Mac)
  • Previous suggestion: Alt+[ (Windows) / Option+[ (Mac)
  • Accept word-by-word: Control+→ (Windows) / Command+→ (Mac)
  • Open multiple suggestions panel: Ctrl+Enter (VS Code/JetBrains)
  • Open inline chat: Ctrl+I (VS Code) / Ctrl+Shift+I (JetBrains)

Study Strategy

Recommended 4-Week Study Plan

  1. Week 1 — Foundations:
    • Complete GitHub Copilot Fundamentals Part 1 (Microsoft Learn)
    • Complete GitHub Copilot Fundamentals Part 2 (Microsoft Learn)
    • Take the module assessments in each learning path module to check understanding
  2. Week 2 — Deep Dive (High-Weight Sections):
    • Study Copilot in IDE & CLI and Capabilities & Policies pages (50-60% of exam weight)
    • Read: Plans documentation, IDE suggestions docs
  3. Week 3 — Cover Remaining Sections:
    • Study Responsible AI (memorise the 6 principles)
    • Study Data & Architecture (trace the full lifecycle)
    • Study Prompt Engineering (zero-shot vs. few-shot, open tabs)
    • Study Developer Productivity (slash commands mapped to scenarios)
    • Study Privacy & Safeguards (fnmatch patterns, 30-min delay, CLI exception)
  4. Week 4 — Practice & Reinforcement:
    • Take the official Microsoft practice assessment — review every wrong answer
    • Do practice sessions on GH Certified (aim for 80%+ accuracy)
    • Revisit every table and callout marked "Exam Tip" or "Must-Know"
    • Run through this page's Key Caveats section as a final check

Hands-On Practice (Essential)

  • Install the Copilot extension and use it daily — exam intuition comes from real experience
  • Practice all slash commands: /explain, /fix, /test, /doc
  • Try the Copilot CLI: gh copilot suggest and gh copilot explain
  • Use all four modes: inline, chat, Edit Mode, and Agent Mode on real code
  • Create a .github/copilot-instructions.md in a test repo
  • Set up content exclusions at the repo level and verify they work
  • Practise few-shot prompting with custom patterns vs. zero-shot for common tasks
  • Use @workspace, #file, and image attachments in Copilot Chat
ⓘ Official Instructor-Led Training

The GH-300T00-A: GitHub Copilot is a 1-day instructor-led course (or self-paced equivalent) aligned to the exam. It covers responsible AI, ethical risks, and hands-on Copilot usage. If you prefer structured classroom learning over self-study, this is the official training pathway.

Day of the Exam

Practical Tips

  • Time management: 100 minutes is generous — aim for ~1.5 minutes per question
  • Flag and return: If unsure, flag the question and come back to it
  • Read carefully: Pay attention to qualifiers like "always", "never", "best", "most appropriate"
  • Eliminate wrong answers: Often 1–2 options are clearly wrong; eliminate them first
  • Think about plan differences: Many questions hinge on Individual vs. Business vs. Enterprise
  • Context matters: Scenario questions test whether you know which feature/tool to use for a situation
  • Interactive questions: Take your time with interactive components; they may be weighted differently
⚠ Online Proctoring

If taking the exam online: ensure a clean desk, stable internet, working webcam/microphone, and a quiet room. Close all unnecessary applications. Check online exam requirements ahead of time.
